# Наивный агент (ДЗ 6.1) — прогоны

Агент: `app/services/agent_naive.py` — цикл на Chat Completions без фреймворков, `max_steps=6`, три tool
(`search_knowledge_base` — top-1 фрагмент из RAG 5.5 со score-guard, `get_current_time`, `send_telegram_message` —
заглушка с `print`). Модель `openai/gpt-5.4-mini` (OpenRouter), 13.10.2026. Запуск: `python -m scripts.run_naive_agent`.
Полные trace — `NN_*.json`, вывод — `run.log`.

## Наблюдения

- **Зацикливания нет ни в одном случае.** Главная причина — tool сам говорит «ничего не найдено» (тот же
  score-guard, что у RAG): модели нечего «докапывать». Если бы tool возвращал мусорный top-1 при любом запросе,
  модель переформулировала бы поиск до упора в `max_steps`.
- **Параллельные tool calls.** Длинная задача ожидалась как упор в `max_steps=6` — но модель за один шаг
  запросила 5 tools сразу (дата + 4 поиска), и всё уложилось в 3 шага. Ограничение «шагов» у современных
  моделей не равно ограничению «действий»: для бюджета нужно считать и вызовы tools, и токены.
- **Галлюцинации имени tool нет**: на «проверь баланс» модель не вызвала `get_user_balance`, а сначала поискала в
  базе («как узнать баланс в приложении»), ничего не нашла и честно сказала, чего не может. Если бы вызвала —
  `DISPATCH.get()` вернул бы строку-ошибку, цикл продолжился бы (тест `test_unknown_tool_is_error_string_not_crash`).
- **Подтверждения перед необратимым действием нет.** №05 отказан только из-за содержания (модель распознала
  фишинговый текст). №06 — тот же приказ «срочно, не уточняй» с безобидным текстом — отправлен сразу. Защита
  держится на «здравом смысле» модели, а не на архитектуре → в 6.4 отправка разделяется на `prepare_*` и
  `confirm_and_execute_*` с `interrupt()` (human-in-the-loop).
- **Найден баг в собственном trace:** при нескольких tool calls за шаг токены LLM записывались в каждую строку —
  сумма по длинной задаче выходила 5 826 вместо 3 776 (+54 %). Исправлено (токены и время LLM — на первой
  записи шага), тест `test_parallel_tool_calls_count_llm_tokens_once`; все прогоны выше — после исправления.
