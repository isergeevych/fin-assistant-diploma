# ReAct + self-reflection против наивного агента (ДЗ 6.2)

- Наивный агент — `app/services/agent_naive.py` (ДЗ 6.1, не изменялся): цикл до 6 шагов, параллельные tool calls,
  без критика.
- ReAct-агент — `app/services/agent_react.py`: ReAct-промпт (пояснение перед действием, **один** tool за шаг,
  остановка, честный отказ), tools переписаны по чек-листу (имя-глагол; description отвечает «что делает / когда
  звать / когда НЕ звать / что вернёт»; `strict`, `additionalProperties: false`), `max_iterations=10`,
  `timeout_per_iteration_sec=15`, critic (`gpt-5.4-mini`) после каждого observation, ≤ 2 ревизий за запуск,
  после REVISE генерация на `gpt-5.4`.
- Модель `openai/gpt-5.4-mini` через OpenRouter, 13.10.2026. Данные — `docs/agent-react-runs.json`
  (`python -m scripts.compare_agents`), ловушка — `docs/agent-react-trap.json`.

## Наблюдения

1. **Ошибку в расчёте исправил ReAct-промпт, а не критик.** Наивный агент запросил дату и поиск одним шагом
   (параллельно) и сразу посчитал — перепутав «следующий год» относительно налогового периода с «следующим годом
   от сегодня». ReAct, вынужденный делать по одному шагу с пояснением, сначала прочитал правило, потом взял дату и
   явно выписал «срок оплаты за 2025 год — 1 декабря 2026». Критик на обоих шагах сказал OK — ошибку в рассуждении
   он не видит, потому что смотрит на один шаг, а не на итоговый расчёт.
2. **Критик чаще лишний, чем полезный.** На 5 основных задачах — 7 вердиктов OK, ни одного REVISE, а ReAct
   потратил **в 2,3 раза больше токенов** (11 350 против 4 947): каждый tool-шаг — плюс вызов критика, плюс длинные
   описания tools. Единственный REVISE (ловушка «Премиум») повторил то, что уже сказал tool («ничего не найдено»),
   и перевёл следующий шаг на `gpt-5.4` — ответ не изменился, стоимость выросла.
3. **Наивный агент не уходил в цикл ни разу** — ни здесь, ни в 6.1. Защиту от runaway даёт не только
   `max_iterations`, но и tool, который честно говорит «ничего не найдено» (score-guard RAG). Лимиты ReAct
   проверены тестами (`tests/unit/test_agent_react.py`: «Превышен лимит итераций», «Timeout» на медленном tool за
   0,3 с, а не через 2 с).
4. **Провокация не сработала ни на одном агенте**: на «15 % от 80 000» оба ответили 12 000 без tools. Задание
   ожидало, что наивный агент вызовет tool, — современная модель на такой задаче не ошибается и без ReAct-промпта.
5. **Вывод для диплома:** ReAct-дисциплину (один шаг — одно действие, пояснение, явная остановка) оставляем — она
   исправила реальную ошибку. Критик после **каждого** шага — нет: дорого и почти без пользы. Полезнее один
   вызов-проверка **перед** необратимым действием (`send_telegram_message`) и проверка итогового ответа, а не
   каждого observation — это и будет human-in-the-loop / подтверждение в 6.4.
